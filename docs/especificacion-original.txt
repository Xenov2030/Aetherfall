1. ALOJAMIENTO Y RESTRICCIONES TÉCNICAS

La aplicación se desplegará en Vercel.

NO usar Supabase para ninguna función: base de datos, autenticación, almacenamiento ni servicios auxiliares. No tengo créditos disponibles.

Si el repositorio ya depende de Supabase, identificá esas dependencias y planificá su reemplazo preservando los datos existentes.

Elegí una arquitectura mantenible y compatible con Vercel. Si empezás desde cero, preferí Next.js con TypeScript, salvo que exista un motivo concreto para otra elección.

Para base de datos, autenticación y almacenamiento:
- Evaluá alternativas que puedan comenzar sin costo.
- Verificá las condiciones actuales en documentación oficial antes de elegir proveedores.
- Explicá límites, requisitos y posibles costos.
- No prometas que toda la aplicación será gratuita.
- No contrates servicios ni actives planes pagos sin mi autorización.
- No des por disponibles cuentas o credenciales.

Requisitos técnicos:
- Base de datos persistente externa.
- Almacenamiento de objetos para imágenes y documentos.
- No guardar archivos subidos ni datos persistentes en el sistema de archivos de las funciones de Vercel.
- Archivos privados mediante autorización y enlaces temporales cuando corresponda.
- No depender de procesos permanentemente encendidos.
- Credenciales exclusivamente en variables de entorno del servidor.
- Separar datos y credenciales de producción y pruebas.
- No utilizar localStorage como almacenamiento principal.
- Evitar dependencias innecesarias.

Si falta configurar un servicio externo, avanzá con el código que puedas verificar y documentá exactamente qué falta. No simules conexiones exitosas.

2. OBJETIVO DEL PRODUCTO

Aetherfall tiene dos experiencias:

MÁSTER:
Un archivo privado y organizado para imágenes, mapas, preparación de sesiones, información del mundo, personajes, reliquias, villanos, mecánicas e ideas futuras. Permite administrar lo que sabe y recibe cada personaje.

JUGADORES:
Una ficha interactiva de apoyo y respaldo de la hoja de papel, acompañada de una ayudamemoria: resúmenes, descubrimientos, inventario, misiones, cartas y vivencias.

La partida sigue siendo presencial y usamos papel y lápiz. La aplicación debe reducir trabajo y acompañar la partida, sin exigir registrar cada acción.

Nombre: Aetherfall.
No agregar un subtítulo obligatorio.
Interfaz y documentación en español.

3. PRINCIPIOS FUNDAMENTALES

- El máster controla el canon y las revelaciones.
- Cada personaje accede a lo que vivió, descubrió o recibió dentro de la historia.
- El conocimiento se administra por personaje.
- Vincular contenido a una sesión no concede acceso.
- Mover archivos nunca los publica.
- El contenido nuevo del máster es privado por defecto.
- Las aportaciones de jugadores no cambian automáticamente el canon.
- Las actividades voluntarias no dan ventajas mecánicas.
- No inventar atributos, niveles, habilidades, historia ni inventarios.
- Diferenciar información vigente, planeada, rumor o creencia y descartada.
- Separar lectura, edición, publicación y descubrimiento.
- Comprobar permisos en el servidor.

- Relato de cierre.
- Asuntos pendientes.
- Punto desde donde retomaremos.
- Participantes.
- Recursos relacionados.
- Estado de preparación y realización.

La introducción es mi narración para poner en contexto a los presentes.
El cierre es mi narración para despedir el encuentro.

No representan necesariamente el comienzo y final de una escena: podemos terminar durante una conversación, viaje o combate.

Conservar borradores y versiones finales.

La crónica completa pertenece al archivo privado del máster.
Permitir compartir fragmentos y preparar versiones para personajes o grupos de destinatarios, reutilizando contenido sin duplicación innecesaria.

No asumir que todos reciben el mismo resumen.
Un personaje ausente no recibe escenas que no presenció.

Cada imagen, enlace y documento dentro de un resumen también debe respetar sus permisos.
